# Desktop sketch preview

Active source: `I:/Projects/Draw3d`.

The desktop test page is `http://localhost:5173/desktop.html`. Double-click the canvas to toggle freehand drawing. Middle drag rotates; Ctrl-middle drag pans; Shift-middle drag or the wheel zooms. Choose a plane/face before drawing when needed. Type a correction and Send, or enable the microphone. The existing VR edition remains at port 18889.

Current desktop workflow: deterministic fitting runs in the background and its shapes/diagnostics are hidden. Only AI-generated work is shown as an uncommitted preview. All model moves refine the same draft; one Accept commits the completed proposal. The small discard control restores the saved design. Local fitting measurements below are historical; those overlays were removed following the user request.

The model receives the original drawing view, a drawing overview/result view, origins/homographies, current geometry versions, and an ink catalog. Raw point arrays, duplicate fit paths and diagnostics are retained server-side. `project_sketch` chooses strokes, target plane, orthographic or recorded-camera projection, lines/splines/mixed, and whether coordinates are returned. `apply:true` produces editable figures in the same model move. `apply_sketch_fit` applies a cached fit ID after checking its source revision. Straight spans in a mixed profile use exact collinear cubic controls; curved spans keep their cubic controls. No model-written coordinate arrays are required for these tool actions. Tools are optional; analytic circles/rectangles and other direct edits remain available.

Desktop native actions use the existing compact `parametersJson` encoding, decoded and validated by the same local operation/parameter/version checks. Exact current topology inspections, error feedback, clarification answers, feature collaboration and previous failed proposals remain available. VR contracts are unchanged. Automatic desktop refinement waits 350 ms after fitting rather than 2200 ms; manual Send is immediate.

For this local preview, start the existing native backend services first. `scripts/run-desktop-preview.mjs` builds a source overlay from `.cache/desktop-preview.tar`, reuses the existing secret mounts/workers without copying secrets, and creates an isolated app-data volume at port 18890. It is a local testing helper tied to this machine's existing Docker installation. The normal server deployment remains `compose.yaml` plus `deploy/compose.terra.yaml`; the new source files are included by its regular app build.

Start the source frontend with `DRAW3D_BACKEND_URL=http://127.0.0.1:18890` and `npm run dev`. For production, run the normal `npm run build` and deploy the rebuilt app image. No USB connection is involved.

Checks: `node --test tests/desktop-sketch-fit.test.mjs tests/desktop-sketch-tools.test.mjs`. Browser: `DRAW3D_FOCUS_TEST_URL=http://localhost:5173` and Playwright `tests/desktop-sketch-preview.spec.js`. The optional paid end-to-end smoke test is `tests/desktop-sketch-live.spec.js`, enabled only with `DRAW3D_LIVE_SKETCH_TEST=1`. It uses synthetic mouse ink and the configured backend model, creates real editable native sketch geometry, and records actual timings in `artifacts/desktop-sketch-live-report.json`.

The two-second goal is measured separately for local feedback and completed AI edits. Never report a local preview as a completed model edit. External model and native engine time can exceed two seconds; inspect the recorded timing events for the real durations.

Explicit plane/face clicks are recorded as the stroke's `drawingTarget`. **Automatic** clears that selection and marks its camera-aligned capture plane as provisional. The model receives the available reference planes and support-inference instructions and can project to an appropriate support. Native geometry selection yields clicks to a visible reference plane so plane selection keeps working after selecting a body. Drawing never silently inherits a previous body's identity just because it was recently edited.

## Broader live comparison

`tests/desktop-model-capabilities-live.spec.js` exercises real mouse drawing, real model requests and real native edits. Enable with `DRAW3D_MODEL_EVAL=1`, set `DRAW3D_FOCUS_TEST_URL` and `DRAW3D_EVAL_LABEL`. Eight requests/checks cover rectangle, circle, exact radius update, mixed curved/straight profile, Top-plane placement, exact CAD block, a centered four-hole pattern, and all-edge fillets. The final observed timings and checked feature parameters are in `artifacts/desktop-model-comparison.md` and `.json`, generated with `node scripts/summarize-desktop-model-eval.mjs`.

Both Luna low and Terra low passed 8/8 checks after adding model-selected analytic `circle` and `rectangle` kinds to `project_sketch`; the older tool had encouraged copying those shapes as splines. Luna's first fillet attempt failed before model output because of DNS and passed on its separately logged retry. That failure remains in the report. All native cases passed solid validity, volume and watertightness checks; pattern parameters and all-edge coverage were independently checked from the executed feature history.

For isolated model comparisons, `scripts/run-desktop-preview.mjs` accepts `DRAW3D_PREVIEW_NAME`, `DRAW3D_PREVIEW_PORT`, `DRAW3D_PREVIEW_MODEL`, and `DRAW3D_PREVIEW_REASONING`. The latter sets `DRAW3D_DESKTOP_REASONING` in the backend; this is an explicit override of the previous forced Terra-medium desktop routing. VR default routing remains unchanged. Luna evaluation backend: 18891, static frontend: 5181. Terra-low evaluation backend: 18892, static frontend: 5182. Both frontend previews serve the same compiled bundle, proxy their corresponding backend, and use separate app-data volumes with the existing native workers. Start a frontend with `DRAW3D_BACKEND_URL` set and `vite preview --outDir .cache/desktop-web --host 127.0.0.1 --port 5181` (5182 for Terra). The main 5173 desktop page stays on Luna low with the corrected tool harness.

Approval preview update: desktop fitting continues numerically in the background, but all local fit lines, deterministic solid ghosts and fit diagnostics are hidden. AI moves are evaluated as one staged design. The visible Preview bar has one Accept button, enabled after background construction finishes; discard restores saved geometry and retains input strokes. Canonical session data and shared-model assets remain unchanged until Accept. Unaccepted drafts and their input strokes are persisted separately and recover on reload. Normal Desktop/VR switching waits for accept/discard. Acceptance/discard is recorded server-side and linked across draft runs; only the final run gets a direct humanAccepted label, so intermediate corrected outputs are not falsely labelled accepted.
