# Drawing intent and plane alignment

The earlier vessel construction was the wrong solution: it imposed a pot/bowl layout and a section-width estimator tilted the latest user outline. The user clarified that they intended something like a cup body, with attention to horizontal lines. That implementation and its object-specific Decisions choices have been removed. This document supersedes the previous vessel-template notes.

The Decisions API now chooses generic measured vs simplified outlines, primitive representation, closure, symmetry, role and original-plane alignment. It receives the original ink image and plane/frame, per-stroke measurements, and long straight-run orientation evidence. No taper-derived canonical view, object-specific proportions, neck/rim/shoulder template or keyword classifier determines the geometry. Prompts favor supported H/V lines and axes in the sketch plane while preserving deliberate rotation, curves and distinct components.

The numerical fitter finds long straight runs independently of curved sides. In simplified, plane-aligned mode, it regularizes departures around supported H/V runs before finding corners. Long runs spanning most of a boundary allow more freehand correction; shorter runs use tighter bounds. Selected line edges remain straight cubic segments while other sections remain curves. Closed one-axis symmetry pairs the two contour halves at actual mirror-axis crossings, averages corresponding samples by least squares, and simplifies the result. This avoids an arbitrary pen-start correspondence creating bumps or sloping the rim. The saved reflection/line constraints remain verified during editing. Explicit tracing mode bypasses abstraction.
