# Google Cloud deployment

Draw3D uses a public sign-in gateway and a separate private Cloud Run service for each Google subject. The gateway checks a Google ID token (audience, issuer, signature, expiry, verified email and nonce) and an invitation passcode. It issues a signed HttpOnly, Secure, SameSite cookie. Every write requires the configured same origin. The server ignores client-supplied workspace identities and supplies its own platform identity to the private worker.

Each worker has one instance maximum and zero minimum instances, its own restricted Cloud Storage prefix, a separate app process and separate native Blender/FreeCAD processes. Browser IndexedDB names also include the signed-in user's workspace namespace. Gateway traffic and worker traffic use request-based CPU billing. Cold starts are expected after inactivity. Storage, image hosting, builds, network and model calls can still incur usage charges. The default invitation capacity is ten workspaces; increase `MAX_WORKSPACES` on the gateway deliberately when needed.

OpenAI remains the primary provider with the existing model defaults. Its key is mounted from Secret Manager as `/run/secrets/openai/key`, loaded only by the backend. Google Cloud Vertex AI is the fallback when the key is absent or the primary provider has a transient failure. No user API key belongs in an image, browser bundle, source file or build argument. Secret changes require rolling the worker revisions because the backend reads its key on startup.

The active-user limit is two distinct Google accounts; multiple tabs of one account share a slot. The gateway must have both service and revision maximum instances set to **1**, minimum **0**, because the capacity coordinator is held in that gateway process. A 20-second workspace heartbeat renews a 90-second idle lease; sign-out releases it immediately, and in-flight requests retain their slot. Additional accounts receive HTTP 429 and a waiting screen before a worker is provisioned or woken. `MAX_WORKSPACES=10` limits historical allocated private workspaces, separately from this two-user activity limit. A restart renews admission from active clients; this is an app capacity control, not a hard spending budget.

The main workspace is a human + AI CAD harness: describe or sketch one step, review it, choose **Keep step**, then modify the same editable body. Explicit next-step requests use the full native operations and current geometry; automatic ink fitting retains its sketch pipeline. Set `DRAW3D_NATIVE_HARNESS_TOOLS=1` on workers. Internal agent transcripts are excluded from the speech input queue so a request cannot submit itself repeatedly. Only the first newly created body reframes the camera automatically. Native bodies also appear in Parts. **Pause audio** releases microphone capture and pauses playback; **Resume audio** starts capture again.

Embedded CAD mutations recover Build mode from a locally persisted View/Tweak mode while preserving ownership/conflict restrictions. The pinned bundle patch exposes the actual command rejection to the parent and session activity log. Browser errors and unhandled rejections also enter each account's existing private session log, with credential-like strings redacted. Operators can collect account-scoped application records and Cloud Run logs for incident diagnosis; raw user recordings and prompts should stay out of source control and public reports.

Build `deploy/cloud/cloudbuild.yaml` with the prepared `public/cad`, `public/sculpt`, fonts and PDF viewer assets. The source upload excludes credentials, private recordings, build caches and Git metadata. Native runtime downloads use the pinned SHA-256 values from the existing Linux deployment.

The gateway needs `GOOGLE_CLIENT_ID`, `PUBLIC_ORIGIN`, `GOOGLE_CLOUD_PROJECT`, `CLOUD_REGION`, `WORKER_IMAGE`, `WORKER_SERVICE_ACCOUNT`, `WORKSPACE_BUCKET`, plus `SESSION_SIGNING_KEY` and `PASSCODE_HASH` supplied by Secret Manager. `PASSCODE_HASH` is a salted scrypt hash of an 8–12 digit invitation code. The worker service account has no public invoker binding. Grant invocation to the gateway service account, storage access only to the dedicated workspace bucket, and secret access only to the required named secrets. Cloud Run also requires the gateway, as the worker deployer, to have Artifact Registry Reader on the deployment image repository.

The existing Vercel deployment is a separate static preview; this Google Cloud stack runs the native engines and backend. Do not copy a user's old recordings or credentials into a new tenant.

Checks: `npm test`, `node --test tests/vertex-cloud-fallback.test.mjs`, `node --test deploy/cloud/auth.test.mjs deploy/cloud/gateway.test.mjs`, and `npm run build` with the prepared assets. Use synthetic geometry for a live native smoke test and verify anonymous API requests get rejected before sharing the URL.

Run `npm run test:cad-runtime` for CAD readiness/mode recovery, microphone release, transcript routing, and native restart checks. Capacity checks are `node --test deploy/cloud/presence.test.mjs deploy/cloud/presence-browser.test.mjs` (the browser fixture uses local Windows Edge). Native engine startup allows 90 seconds by default for a cold container; `DRAW3D_NATIVE_STARTUP_MS` adjusts it within 1–180 seconds. Geometry operation execution retains its separate 60-second limit.

The gateway injects a seven-card tutorial into the main workspace. Authenticated `/learn/visit` creates an immutable `onboarding/v1/<account-key>.json` marker with a generation precondition, using the gateway's existing Object Creator grant. Tutorial and microphone choices are also saved in account-scoped browser storage. The Tutorial button reopens the cards. Four small WebP frames come from the supplied demo recordings; full videos are not shipped. Enable microphone invokes the existing app capture control inside a click gesture, so the app owns the stream and browser permission prompt. Denied permission and typed-input alternatives remain available. Run `node --test deploy/cloud/onboarding.test.mjs` with local Edge for browser checks of cards, account separation, permission gesture, denial recovery and mobile layout.

Workspace launches use `/open` with visible startup stages while `/auth/prepare` wakes the private runtime. Its short-lived signed readiness cookie is account-bound and supplements the required sign-in session. The desktop and CAD editor also show loading progress. CAD ignores the iframe's initial `about:blank` event, allows time for a first download/restoration, and offers Retry CAD without deleting saved work. Static asset responses may be cached privately for a day; account HTML and APIs remain uncached.

Microphone setup reports permission granted immediately after capture opens, then reports recording separately. Neural voice detection has a bounded startup and falls back to the existing audio-level detector when unavailable or slow. A late detector is released without opening a second capture path. The on/off state is emitted immediately, including when the input is silent. Run `npm run test:startup` for the startup regressions.
